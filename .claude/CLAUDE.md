# CLAUDE.md

## Project Overview

This is a **Symfony bundle** (`jmonitor/easyadmin-bundle`) that adds live monitoring pages to an EasyAdmin 5 backend: system, PHP, FrankenPHP, MySQL, PostgreSQL, Redis and Symfony metrics collected when the page is opened and refreshed by polling while it stays open. No worker, no history, no charts: the present only.

It reuses the collectors of `jmonitor/collector`, instantiated by this bundle's own service wiring. The Symfony collectors (`src/Collector/Symfony/`: `SymfonyCollector`, `CommandRunner`, the messenger/scheduler/flex sub-collectors) are a copy of those of `jmonitor/jmonitor-bundle`, which must not become a dependency: being a `symfony-bundle`, Flex would register it in every application. Keep the copy's payload shape identical to the original, except the `errors` key it adds (sub-collector name => failure message) so that the Symfony tab can show why a card is empty. The bundle needs no account and no API key.

## Architecture

Request flow: `Controller\MonitoringController` → `Detection\ComponentRegistry` → `Snapshot\SnapshotProvider` → `View\ViewFactory` → Twig.

- **Routes**: the controller carries `#[AdminRoute('/jmonitor', name: 'jmonitor')]` and is tagged `ea.admin_route_controller`; EasyAdmin creates `<dashboard>_jmonitor_index`, `_component` (`/{component}`), `_fragment` (`/{component}/fragment`) and `_refresh` (POST) under every dashboard. The dashboard route name comes from `AdminContextProviderInterface::getContext()->getDashboardRouteName()`. Access is left to the application's security, like its CRUD controllers (an `access_control` rule on the dashboard path); the `permission` option adds an `isGranted()` check in the controller, before anything else, throwing an `AccessDeniedHttpException` wrapping Security's `AccessDeniedException` (403 outside a firewall, the firewall's handling inside); an empty string resolved from an env var is a `LogicException`; the option is refused at container build time when no `SecurityBundle` (or child) is in `kernel.bundles`, the only thing the temporary extension container knows; `loadExtension()` refuses a literal empty string, not the config tree, because Symfony validates env placeholders with an empty string.
- **Detection** (`src/Detection/`): one `ComponentDetectorInterface` per `Component` enum case, tagged `jmonitor_easyadmin.detector` with the component value as index. A `Detection` carries a list of `Instance`s (id = Doctrine connection name for MySQL and PostgreSQL, configured connection id for Redis, `null` for the implicit instance of System, PHP, FrankenPHP, Symfony and auto-detected Redis). `ComponentRegistry` applies the `enabled` setting (`auto` keeps what is found, `true` keeps the component with one instance in error, `false` drops it), memoizes per request and implements `ResetInterface`. MySQL and PostgreSQL enumerate the connections of their driver through `DoctrineParams::instances()`: every one when `connections` is empty (a connection whose service throws is skipped, reported to `SkippedConnectionReporter`, and cited in the error of a forced component left without instance), but those matching a pattern of the root option `exclude_connections` (`fnmatch()`, shared by both detectors since each one walks every connection; a connection listed in `connections` matching it is refused at build time), which are never built since DoctrineBundle opens a connection with `mapping_types` and no `server_version` while building it; exactly the configured ones otherwise, an unusable configured connection becoming an instance in error; the processed configuration has no `connection` key: the deprecated option, MySQL only (PostgreSQL never had it in a release), is merged into `connections` by a validation rule of the component, once every configuration file is merged (a later file overrides it, `connections` in another file is refused). Redis lists the `connections` of its configuration (id => `dsn` or `service`, the deprecated `dsn`/`service` merged into `connections.default` the same way), each one an instance, in error when the service is unknown (referenced with `ignoreOnInvalid`, so the container still compiles) or the DSN invalid or empty; without any, one implicit instance from `framework.cache.default_redis_provider` or `REDIS_URL`; the pill detail is the server without credentials. FrankenPHP is found when the PHP SAPI is `frankenphp` (`FrankenPhpDetector`, the SAPI read as a constructor default at service build time, never in `services.php`: the container is compiled under the CLI SAPI); its collector is the library `FrankenPhpCollector` reading the `endpoint` (Caddy admin API Prometheus export), wrapped in `Collector\FrankenPhpEndpointCollector` (an unreachable endpoint or an export without `frankenphp_*` metrics becomes a collect error naming the `metrics` global option of the Caddyfile) and given a `Collector\CachedShellExecutor` so `frankenphp version` runs once per `static_ttl` (one item per collector, `jmonitor_easyadmin.shell.frankenphp`, holding command => output; the command runs through `Collector\ProcessShellExecutor`, whose empty output is an exception with the exit code and stderr, logged as a warning and dropped by Refresh through `Collector\RefreshableCollectorInterface`). Detection never touches the monitored servers (only the cache pool, through `SkippedConnectionReporter`, when a connection is skipped): the detectors read the Doctrine connection parameters (`driver` `pdo_mysql`/`mysqli`/`pdo_pgsql`/`pgsql` or a `driverClass`, `dbname`), Redis opens its DSN lazily (`?lazy=1`), FrankenPHP reads its endpoint at collect time only, so a dead server shows up as a collect error inside the tab. A connection without host, on a loopback host or through a `unix_socket` counts as local: on Linux it also gets `HostRamCollector` (`system.ram_total`, static), the only source of the InnoDB and `shared_buffers` RAM ratios, hidden otherwise. The controller picks the instance from the `connection` query parameter (absent or empty = the first one, unknown = 404); `layout.html.twig` draws the `jm-instances` pills of `navigation.pills` (see Views). MySQL connections are grouped by server: `DoctrineParams::server()` builds a `Server` (identity from the primary's `unix_socket`, else lowercased host defaulting to `localhost` and port defaulting to 3306), attached to the `Instance` as `$server` when the detector passes `byServer: true`; `Instance::serverKeyPrefix()` is `<component>.%server.<xxh128(key)>.` or null. `DependencyInjection\DoctrineConnectionsPass` fills the detectors' connection locator from the `doctrine.connections` parameter; `JmonitorEasyAdminBundle::prependExtension()` reads `framework.cache.default_redis_provider`.
- **Collection** (`src/Collector/`, `src/Snapshot/`): a `CollectorSet` lists `CollectorSpec`s (collector, `Lifetime`, `trackDelta`). `Lifetime::Dynamic` = `polling_interval` seconds (min 1), `Minute` = 60, `Static` = `static_ttl`. `SnapshotProvider` collects an `Instance` and caches each collector's `CollectorResult` under `jmonitor_easyadmin.collect.<prefix><name>` in the configured PSR-6 pool (`cache.app` by default), `prefix` being `Instance::keyPrefix()` (`<component>.<id>.` for a named instance, empty for an implicit one, the same prefix keying the deltas); a failure is cached for the dynamic lifetime and its message carries the cause of a wrapped exception. A `CollectorSpec` flagged `perServer` (`mysql.status`, `mysql.variables`, `system.ram_total`) is collected, cached and delta-tracked once per server under `serverKeyPrefix()`: only successes are shared, a failure stays with the connection that hit it since it may come from that connection (credentials, unknown database, privileges). Refresh drops the server entries too, and the collect lock is per server. The MySQL and PostgreSQL collectors of a connection share a `Collector\FailFastDoctrineAdapter`: a query failing while the connection is not open throws an `UnreachableServerException`, rethrown to the next queries without a new attempt (a query failing on an open connection, a missing privilege, does not; a `ConnectionLost` is retried once only when the connection was open before the query), and such a failure is cached for `max(60, polling_interval)` seconds. A marker `jmonitor_easyadmin.collecting.<component>[.<id>]` holding a token, best effort, expiring after `max(300, that time)` and removed by its owner only or by Refresh, lets one request at a time collect an instance; another request gets `SnapshotProvider::IN_PROGRESS`, uncached, for the collectors it misses, shown once as an info notice (`ComponentSnapshot::inProgress()`), not as errors. `DeltaCalculator` keeps a reference sample (`jmonitor_easyadmin.previous.<prefix><name>`) and yields a `Delta` when the new sample is between 1 second and `max(300, 2 × polling_interval)` seconds after it; a sample less than `polling_interval / 2` after the reference (a Refresh) is compared with it without replacing it; a counter that went down gives no value.
- **Metrics** (`src/Metric/`): metric keys (`system.ram_usage`, `php.opcache_hit_rate`, `mysql.connections_usage`, `redis.hit_rate`…) key the thresholds in `config/ranges.php` (`Ranges`, `Badge`) and the help links (`MonitoringExtension::HELP_URL`). `Ratios` computes percentages (and `average()` means, such as the FrankenPHP execution time) from the delta when it has traffic, else from the cumulated counters (`Rate::isSinceStart()`, with `Rate::hint()` as the hint: "since server start" by default, the `since` given by the view otherwise, "since stats reset" for PostgreSQL); `GaugeFactory` turns values and rates into `Gauge`s.
- **Views** (`src/View/`): one read-only view per component (`SystemView`, `PhpView`, `FrankenPhpView` with one `FrankenPhpWorkerView` per worker script, `MysqlView`, `PostgresqlView`, `RedisView`, `SymfonyView`) built from a `ComponentSnapshot`; `Values` normalizes the payload types. `InstanceNavigation::of()` turns the instances and the current one into `NavigationItem`s: one pill per server (host label, `host:port` when two servers share a host) for a MySQL component with several servers, one pill per instance otherwise, plus the databases of the current server (none for one, pills for two, a drop-down from three). Templates contain no logic beyond formatting: badges are `Badge` objects built by the views, the peak bars a `Metric\Peak`.
- **Templates** (`templates/`, namespace `@JmonitorEasyAdmin`): `layout.html.twig` extends `@EasyAdmin/page/content.html.twig` and defines the inner block `jm_content` (EasyAdmin owns the `content` block, never override it); `fragment.html.twig` renders only `jm_content` for the polling; the MySQL template shows the server cards, then a Database block (`Database · <name>` alone, pills or a drop-down); `component/*.html.twig` extend one or the other depending on the `fragment` variable; partials `_card` (title, `?`, badge), `_value_card`, `_sub_value`, `_gauge` (SVG arc, optional detail rows, `bare` inside another card), `_peak` (SVG bar with a peak marker), `_badge`, `_help`, `_rate`, `_kv` (a `Badge` value renders as a badge), `_value`, `_errors`. Twig helpers in `Twig\MonitoringExtension`: `jm_bytes`, `jm_duration` (a float below one second renders in milliseconds), `jm_number`, `jm_ago`, `jm_help_url()`.
- **Front** (`public/`, served from `bundles/jmonitoreasyadmin/` after `assets:install`): `live.js` is vanilla (polls the fragment every `polling_interval` seconds, pauses when the tab is hidden, remembers the Live switch in `localStorage['jmonitor_easyadmin.live']`, keeps the active Bootstrap tab and the scroll of the `.jm-scroll` cards, queries and tables across refreshes (by rank, only when their number did not change), skips a refresh while text is selected in the content, reloads the page on a redirect (fetched with `redirect: 'manual'`, so an SSO on another origin is caught too) or a 401/403 so the firewall shows its login page, goes to the index route on a 404 (the component is gone), and shows "refresh failed" next to "Last update" while refreshes fail); `navigation.js` submits the database drop-down on change (a `<noscript>` button otherwise), and `live.js` skips a refresh while a select inside the content has the focus; `help.js` opens the `?` links in an offcanvas holding an iframe sandboxed with `allow-same-origin` and no `allow-scripts`, created from a `<template>` on the first open, with `?theme=light|dark` taken from EasyAdmin's `data-bs-theme`, and moves the panel under `<body>`; the link keeps its `href` and `target="_blank"`, so a modified click, a missing `window.bootstrap` or a blocked frame still reaches the page; `monitoring.css` styles the gauges with Bootstrap CSS variables. No Chart.js, no Stimulus, no AssetMapper dependency.
- **Wiring**: everything is declared by hand in `config/services.php` (`autowire(false)`), reading the processed configuration from the `jmonitor_easyadmin.config` parameter. The collectors and `Detection\SkippedConnectionReporter` log through `Logging\MinimumLevelLogger`, which forwards warnings and above to the application logger (channel `jmonitor_easyadmin`): sub-collector failures of the Symfony tab land in the application logs, the collectors' per-collect notices do not. The detection runs on every request and both database detectors walk every Doctrine connection, so `SkippedConnectionReporter` keeps a marker in the cache pool to warn once per connection and error per `static_ttl`; it ignores the connections listed in `connections` of an enabled component (their tab shows the error) and swallows its own failures.
- **Robustness rules**: a detector that throws becomes an unavailable component, never a 500 on the whole monitoring; a cached payload whose shape is unknown counts as a miss; the Refresh form carries a CSRF token (`MonitoringController::REFRESH_TOKEN_ID`) checked when the token manager exists; the Redis provider of the Symfony cache may be a DSN or a service id.

## Tests

- `tests/Fixtures/TestKernel.php` boots the full stack (FrameworkBundle, Twig, TwigExtra, TwigComponent, Security, Doctrine on SQLite in memory, EasyAdmin, this bundle) with a configurable bundle and framework configuration; `tests/Fixtures/App/AdminKernel.php` derives from it for `WebTestCase`, with MySQL, Redis and the Symfony sub-collectors disabled, and reads `JMONITOR_TEST_POLLING` (see `PollingDisabledTest`). The test dashboard lives at `/admin` with route name `admin`; in-memory users `admin` (`ROLE_ADMIN`) and `viewer`. `tests/Fixtures/App/ConfigurableAdminKernel.php` takes its bundle configuration, and optionally a throwing MySQL detector, a MySQL detector yielding given instances (`InstancesDetector`), fake Redis client services (`FakeRedisClient`, registered before the optimization passes) or a FrankenPHP detector fed with a SAPI, a Prometheus export and a `frankenphp version` output (`FixtureUrlFetcher`, `FixtureShellExecutor`, exports in `tests/Fixtures/FrankenPhp/*.prom`), from static properties (see `RobustnessTest`, `InstancesTest`, `RedisInstancesTest`, `FrankenPhpTest`).
- Kernel-booting tests call `restore_exception_handler()` in `tearDown()`: FrameworkBundle leaves an exception handler behind on Symfony 8.0 and PHPUnit reports it as risky.
- The MySQL tab cannot be reached by the functional tests, the Redis tab only through a `FakeRedisClient` service and the FrankenPHP tab through the injected fixtures; `tests/Twig/ComponentTemplatesTest.php` renders their fragments from fixture payloads with strict variables on.
- There is no JavaScript test runner.

## Commands

Never prepend `cd [path]` before commands, and never use `git -C "[path]"` for git commands. The shell is already running at the project root.

```bash
composer phpunit        # tests
composer phpstan        # static analysis (level 8)
composer lint:check     # PHP-CS-Fixer check (@PER-CS)
composer lint:fix
./vendor/bin/phpunit tests/path/to/TestFile.php   # single test file
```

Without PHP on the host, run them through a container, for instance:

```bash
docker run --rm --user "$(id -u):$(id -g)" -e HOME=/tmp -v "$PWD":/app -w /app <php 8.2+ image with composer> composer phpunit
```

CI (`.github/workflows/tests.yml`) runs PHPStan and PHPUnit on PHP 8.2 to 8.5 and Symfony 6.4, 7.4 and 8.1, plus a `--prefer-lowest` job checking the floors of `composer.json`, for pushes to `*.x` branches and pull requests; the lint runs once, on the newest combination.

## Conventions

- `declare(strict_types=1)` in every file, full type declarations, PHP 8.2 floor (EasyAdmin 5's own floor).
- Readonly classes for immutable services, constructor injection, attributes for routes.
- Services must be safe under FrankenPHP worker mode: no per-request state kept in shared services unless they implement `ResetInterface` and are tagged `kernel.reset`.
- Never use Yoda conditions.
- Comments: short, factual, only when they say something the code does not.
- Development branch `1.x`; feature branches are merged through pull requests so the CI matrix runs.
- Commit messages and pull request bodies carry no session link such as a `Claude-Session:` trailer.
- This repository is public: no local path, private repository, private project or customer name in tracked files, commit messages or pull requests; no status, to-do list or development notes in tracked files; no description of the jmonitor.io service, which changes on its own schedule.
